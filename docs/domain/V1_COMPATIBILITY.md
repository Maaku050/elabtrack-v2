Audit 15's containment patch is explicitly undeployed. No V1 Firebase access, export, importer, data conversion or migration occurs in Phase 2. Decisions on dataset/cutover/reconciliation remain OPEN-018/026.

## Collection-to-relational compatibility

Mappings below are design inputs, not an accepted importer. For each source retain original system/collection/document ID, source path/hash, batch/export provenance and mapping/reconciliation decisions in separate [provenance candidates](DATA_MODEL.md#deferred-and-conditional-candidates), not miscellaneous legacy fields on every entity. No source password, contact sample or credential is reproduced.

## Legacy status evidence

Audit 04/07 stored vocabulary is `Request`, `Ongoing`, `Ondue`, `Overdue`, `Incomplete`, `Incomplete and Ondue`, `Incomplete and Overdue`, `Complete`, `Complete and Overdue`. Candidate mapping separates pending/checked_out/completed lifecycle from quantitative partial and historical calendar outcome. A `returned` checkbox may disagree with cumulative counts. Treat an unexpected `Due`/`Missing` or other live label as a source variant requiring actual discovery; OPEN-015's historical shorthand does not prove such stored variants.

Snapshot prices/names and original due values are historical evidence even when current catalog differs. Due dates cannot be replaced with return date to force a terminal fit. Missing/invalid source dates remain unknown; `time.Now()` is not a migration fallback. Request items must not be interpreted as issued simply because both used borrowedQuantity. Legacy current stock values alone cannot identify which missing quantities were damaged, lost, retired or concurrent-write corruption.

## Provenance and reconciliation acceptance

**ENGINEERING RECOMMENDATION:** a separately authorized Phase 12 adapter should validate sanitized real-shape fixtures first, manifest completeness/hash and source data types; explicitly map users, every source line, requests, issued custody, cumulative disposition, snapshots, due dates and finance evidence. Immutable source hashes plus mapping paths allow one document to map multiple item rows without losing identity. Deterministic target IDs are optional; transactional unique mappings and conflict detection are essential.

Mapping claim and dependent target writes must commit together. Rerun same source/hash should produce the same lineage and no duplicate effects; changed source/hash or partial prior claims require review. A dry run must be non-writing or use an explicitly isolated disposable target, never the ordinary configured database. Quarantined issues retain restricted evidence and actor decisions; no arbitrary promotion to valid data.

Reconcile before any authorized cutover: unique source→target user/equipment/transaction/line lineage, reserved request/approval holds, issued-minus-disposition outstanding by item and equipment, all bucket/ledger baselines, every historical snapshot/due timestamp, original assessment and adjustment/payment evidence, images actually available, exclusions/unknowns and duplicate collisions. Counts and sums alone do not prove per-item custody or financial correctness. Decisions on an explicit legacy baseline or unknown historical timestamps are blocking the future migration contract; Phase 2 does not pretend they are solved.

Denials/manual deletes absent from the source cannot be reconstructed as known actor events. Keep an explicit evidence gap; notification hints do not create a complete audit trail. No privacy procedure or retention period is invented; authorized data owners must decide exclusion/anonymization while preserving consequential lineage/balances. [DATA_MODEL](DATA_MODEL.md) keeps provenance/issue tables deferred until that scope is confirmed.
