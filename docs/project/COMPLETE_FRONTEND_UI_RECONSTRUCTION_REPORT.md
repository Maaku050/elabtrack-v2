## Shared architecture and narrow backend integration

Pages retain feature hooks → TanStack Query → feature APIs → centralized authenticated transport. Server state is query-owned; local stage/form state and the session-partitioned cart preserve generation fences. Direct-review reads moved into a feature hook rather than issuing transport calls from the page. Borrower Home is a separate lazy module so first-use navigation does not load Staff chart dependencies.

Reusable additions include full-accessible compact `RecordReference`, real-image `BorrowingCard`, shared `EquipmentSelectionCard`, existing 44px `QuantityControl`, compact directory/table styling, the profile editor and read-only account metadata, mobile header contextual action and offline PDF utility. Base UI/shadcn primitives and approved tokens remain; no unrelated visual redesign or component-library replacement.

Compatible backend additions are scoped Mark All Read, bounded complete export-data, truthful days7/30 analytics and due-today read filter, own read-only metadata, current eligibility preview and eligible-before-pagination account listing, and bounded borrowing item summaries. [API contracts](../API_CONTRACTS.md) describe exact permissions/limits. Domain/application retain inward-only dependencies and transaction ports. No migration is introduced. Existing command transactions, locks, stock arithmetic, history, fines, replacement rules and UUID idempotency contracts are preserved.

Final confirmation independently rechecks active/activated current actors, roles, current terms, target eligibility, future due time, available stock and concurrency. Public safe error codes now include existing stale/state/eligibility/export errors while credentials, SQL and arbitrary server messages remain masked. PDF/CSV click handling shares a busy guard; no browser state grants authorization.
