## Delivered scope

Real authenticated Borrower catalog/details with bounded search/category/availability/sort/pagination; Staff/Admin inventory metrics/table/details/category management/equipment create/edit/status/archive; reviewed usable acquisition/removal; Admin-only reviewed available-count reconciliation; immutable movement/audit/history and retry receipts; validated authenticated catalog raster upload/display. No synthetic catalog/category content is seeded into normal data.

Approved physical model is `total_tracked = available + reserved + checked_out + damaged_held`. A is current available physical stock; R/C/D remain separate. Opening/add/remove affects A/T only. Admin reconciliation uses an observed A, explicit reason/confirmation and expected stock sequence; R/C/D stay unchanged. Current loss incidents and replacement liability are not physical buckets. There is no fabricated zero liability, damaged repair/disposal, custody override or return-photo upload.

Paired [000007](../../backend/migrations/000007_inventory.up.sql) adds equipment_categories, equipment, equipment_images, inventory_movements, inventory_audit_events and inventory_operation_receipts. Bigint arithmetic has nonnegative/per-pool2147483647 bounds and wide conservation checks; sequences distinguish stock from metadata versions. Category FK/unique name and equipment-image composite ownership are constrained. History/image/receipt rows are immutable, including owner-level UPDATE/DELETE/TRUNCATE triggers; consequential FKs restrict deletion. Runtime receives named SELECT/INSERT and narrow metadata/A/T/version/image-pointer writes; **no R/C/D UPDATE**, no equipment/history deletion, DDL, tracking access or privileged grants. Down refuses catalog/history rather than deleting it. All ten original000001–000005 migration files are unchanged;000006 remains the Phase5 pair.

Mutations lock the current actor before equipment/category rows, reauthorize current active role, validate strict bounded input and trust Origin, and atomically write stock/movement/audit/receipt. Stale metadata or reviewed count conflicts; identical resource-bound UUID command keys replay, changed payload conflicts. Staff/Admin can create/update equipment/categories/ordinary usable stock; only Admin reconciles. Borrower reads ACTIVE equipment only, cannot write catalog/stock/images or read operational movement history. Inactive/archived detail/images are hidden from Borrowers. Existing account/session/terms architecture remains.

Archive retains all stock and evidence; it blocks R/C and verifies absence of future public borrowings/replacement_obligations tables. Once either appears without connected real liability checks, archive becomes unavailable and fails closed. This is a safe current-domain boundary, not a claim that replacement balances are integrated. Phase7/8 must supply actual outstanding checks and compatible stock movement/grant migrations under account→borrowing/obligation→equipment lock order. Archived metadata/stock is read-only; unarchive is not exposed in this phase. Existing inactive categories may remain attached; new association requires active category. Category inactivity does not silently hide or recategorize existing equipment.

Catalog images use an explicitly bounded local PostgreSQL strategy: PNG/JPEG input<=512KiB,2048/dimension and4M pixels, decode/re-encode PNG with metadata removed, immutable hash/actor/ownership storage. Authenticated current-image-only retrieval is no-store/nosniff. SVG/GIF/arbitrary external URLs/oversized files/dimensions and return evidence are rejected or unsupported. No paid object storage or generic attachment service was added. Database backups include images; future storage scaling/retention requires separate review.
